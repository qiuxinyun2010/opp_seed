# Bundle 交换规则（给 AI 读）

我随后会发给你一个 `bundle.txt`：它是一个项目的**完整快照**，纯文本单文件，里面按段
装着每个源文件的原始字节。请你严格按本规则**读**它，并按同样的格式**回传**修改结果；
我本地会用脚本把回传内容拆回真实文件。

---

## 1. 包的骨架

```text
@@@OPPSEED-BUNDLE 1
@@@ROOT opp_seed
@@@GENERATED 2026-10-30T14:19:17
@@@FILES 97
@@@INCLUDE .gitignore 119
@@@INCLUDE seed.py 56555
@@@INCLUDE ui/启动地图工具.bat 1267
@@@BEGIN
@@@FILE seed.py
<seed.py 的原始字节>
@@@END seed.py
@@@EOF
```

读法：

- `@@@BEGIN` **之前**是元信息，不含任何文件内容：
  - `@@@ROOT` 包根目录名（**段内所有路径都相对它**，例如 `@@@ROOT ui` 时包里就是
    `mapview.py`、`maplib/extract.py`、`data/maps/PSA_MT01.json` 这种），
    `@@@GENERATED` 生成时间，`@@@FILES` 包内文件个数；
  - 随后 **每个包内文件一行 `@@@INCLUDE <路径> <字节数>`**，这就是本包的完整清单
    （`@@@FILES` 的条数应与 `@@@INCLUDE` 行数一致）。清单里没有的文件就不在这个包里。
- `@@@BEGIN` 之后是文件段，一段一个文件：`@@@FILE <参数>` … `@@@END <同样的参数>`。
- **段边界只认 `@@@END <与 @@@FILE 完全相同的参数>`**（含 flag 的顺序）。内容里出现别的
  `@@@` 开头的行（包括 `@@@EOF`）都不影响解析，只有出现与结束标记一字不差的整行才会截断。
- `@@@EOF` **之后**的内容不参与解析，可以自由写说明。

## 2. 两种可选 flag

| flag | 含义 | 回传时怎么处理 |
|---|---|---|
| `b64` | 该文件是二进制，内容体是 base64 文本 | 原样保留，不要解成二进制再回传 |
| `nonl` | 原文件结尾没有换行，包里补了一个 LF | 照抄这个 flag；内容末尾那个 LF 要留着（我在本地解包时去掉） |

没有 flag = 纯文本，内容体就是文件的原始字节。

## 3. 回传时的硬性规则

1. **只回传你改动或新增的文件**（增量包）。没动的文件不要出现在回传里——我本地只写包里列出的文件。
   如果我说「全量」，才把全部文件回传。
2. 回传必须**整包放在一个 Markdown 代码块里**（```` ```text ```` 开头、```` ``` ```` 结尾）。
   原因：包里有 `#` 开头的注释行和 `__name__` 这种双下划线，裸文本会被聊天界面当 Markdown
   渲染，`#` 变标题、`__x__` 变粗体，字符会被吃掉（我这边已经踩过这个坑）。
   代码块之外**不要**写前言、总结、解释、diff；要说的话一律写在 `@@@EOF` 之后、代码块之内。
3. **每个标记必须独占一行**：`@@@FILE …` 单独占一行，内容从**下一行**开始；`@@@END …` 也单独
   占一行。绝不能出现 `@@@BEGIN @@@FILE x.py` 或 `@@@END a.css @@@FILE b.js` 这种挤在
   同一行、或 `@@@FILE a.bat @echo off` 这种标记和正文粘连的写法。
4. 头部可以简化成只有一行 `@@@BEGIN`；每个文件仍必须 `@@@FILE …` / `@@@END …` 成对出现，
   **路径必须逐字配对**（`@@@FILE web/style.css` 配 `@@@END web/style.css`）。
5. 路径用 `/` 分隔，相对于项目根目录；不要 `./` 前缀、不要盘符（`C:`）、不要 `..`。
6. **逐字节保真**：除你需要修改的那几行，不要重排、不要重新缩进、不要删行尾空格、不要
   转换换行风格（原包是 CRLF 就保持 CRLF，`.bat` / `.json` 尤其注意）、不要补/删文件末尾换行。
7. **不许省略**：不能写 `...`、`# 其余不变`、行号、`<省略>`、`同上`。每个回传的文件都必须完整。
8. **新增文件**：新建一段，路径按第 5 条，内容完整。
9. **删除文件不支持**：这个格式没有 DEL 语义，不要用「空的文件段」表达删除。需要删文件时，
   在 `@@@EOF` 之后写一行 `DELETE: <path>`，我手动处理。
10. **二进制不要改**：`b64` 段原样带回。确实需要替换某张图/某个二进制，在 `@@@EOF` 之后说明
    路径和原因，由我在本地处理。
11. 同一个文件只允许出现一次；段的顺序不限，建议与被修改文件在原包中的先后一致。
12. 如果我的要求需要改动的文件**不在 `@@@INCLUDE` 清单里**（本包没收录），在 `@@@EOF` 之后
    说明缺哪个文件，不要自己臆造别处的文件、也不要凭空猜测它的内容。

## 4. 回传前自检

- [ ] 整包是否放在**一个** Markdown 代码块里（```text 开头 / ``` 结尾）？
- [ ] 每个 `@@@FILE` 都有 `@@@END`，且路径逐字一致、数量相等？
- [ ] 每个 `@@@FILE` / `@@@END` / `@@@BEGIN` 是否都**独占一行**，没有和内容或其他标记挤在一起？
- [ ] 每个文件内容完整（没有 `...`、没有截断）？
- [ ] 路径都是相对 `/` 路径？
- [ ] 只包含真正改动/新增的文件，没有把未修改文件一起带上？
- [ ] 换行风格、行尾空白没有被顺手改掉？

## 5. 回传示例

（示例本身就在代码块里；`<...>` 是占位说明。）

```text
@@@BEGIN
@@@FILE seed.py
<seed.py 的完整内容，只改动了你要改的那几行>
@@@END seed.py
@@@FILE tools/new_tool.py
<新文件的完整内容>
@@@END tools/new_tool.py
@@@EOF
改动说明：
- seed.py：新增 X 分支
- tools/new_tool.py：新增工具
DELETE: tools/legacy.py
```

## 附：本地解包（人工执行，与 AI 无关）

```bash
python tools/bundle.py unpack bundle.txt -o . --force   # 还原到项目根，覆盖被修改的文件
python tools/bundle.py unpack bundle.txt -o . --dry-run # 只看会写哪些文件
```
